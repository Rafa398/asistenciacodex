# Actividad de GitHub Classroom: Diseño de una Práctica Temática Pequeña

## Descripción general
En esta actividad vas a **diseñar y documentar** una propuesta de práctica temática pequeña usando uno de estos lenguajes: **ARM64 Assembly, C, Python o Bash**. La meta es que estructures un repositorio real y expliques claramente la idea antes de programar.

## Objetivo de aprendizaje
Al finalizar, serás capaz de:
- Plantear una solución técnica pequeña y viable.
- Justificar la elección de lenguaje según el problema.
- Organizar un repositorio con documentación clara.
- Definir un plan básico de pruebas sin depender de frameworks.

## Lenguajes permitidos
- ARM64 Assembly
- C
- Python
- Bash

## Reglas para mantener el proyecto pequeño
- Enfócate en una sola funcionalidad principal.
- Evita dependencias complejas y configuraciones pesadas.
- No uses frameworks.
- No uses bases de datos.
- No uses Docker ni contenedores.
- No uses servicios en la nube.
- No uses APIs externas.
- Mantén funciones cortas y objetivos concretos.
- Si eliges ARM64 Assembly, limita tu idea a un programa **muy pequeño**.

## Entregables esperados
1. Documentación completa en la carpeta `docs/`.
2. Estructura de repositorio ordenada.
3. Script simple de ejecución en `scripts/run.sh`.
4. Archivo inicial en `src/main.<ext>` (por defecto Python).
5. Plan de pruebas breve en `tests/test_plan.md`.

## Instrucciones para el estudiante
1. Lee todo el `README.md` y revisa la carpeta `docs/`.
2. Completa primero `docs/propuesta.md`.
3. Después llena `docs/caso_de_uso.md` y `docs/plan_de_pruebas.md`.
4. Ajusta `src/main.py` solo con un prototipo mínimo (opcional en esta fase).
5. Verifica ejecución local con `scripts/run.sh`.
6. Sube tus avances al repositorio asignado en GitHub Classroom.

## Criterios generales de evaluación
- Claridad de la propuesta y del problema a resolver.
- Coherencia entre lenguaje elegido y alcance.
- Viabilidad técnica del proyecto pequeño.
- Calidad de documentación y estructura del repositorio.
- Definición de pruebas mínimas realistas.

## Ejemplos de posibles temas
- **Mini Toolkit en ARM64**
- **Asistente de Estudio en Terminal**
- **Reporteador de Información del Sistema**
- **Organizador de Archivos**
- **Juego de Aprendizaje en Línea de Comandos**

## Nota importante
Primero se documenta la propuesta y se justifica la idea. Después, de forma opcional, se implementa un prototipo pequeño.
